# Navigoal — consignes projet

## Règle de conception (obligatoire)

**Toute interface (site web, application mobile, back-office, espace établissement, espace bailleur Navilease…) est d'abord maquettée dans Figma, puis codée.**

1. Produire ou mettre à jour les écrans dans le fichier Figma du projet :
   https://www.figma.com/design/NzAcfIbAFK6tTliGnuE5xq (générateur : `design/maquettes/build.py`, import via `html_to_figma`).
2. Partager le lien et attendre la validation de l'utilisateur.
3. Seulement ensuite, coder en suivant les maquettes validées.

Toute modification visuelle importante d'un écran existant repasse aussi par Figma.

L'ancien collecteur Openverse (`scripts/fetch_illustrations.py`) est conservé mais n'est plus la source. `lib/photos.ts` : `photoMetier` lit ces crédits, `photoFormation` retombe sur le métier visé puis sur le domaine. Crédits visibles sur `/credits/` (page listée au pied de page).
- Poids des images : chaque photo de `web/public/images/` est déclinée en 160, 400, 640 et 840 px par `python3 scripts/variantes_images.py` (`--verifier` contrôle qu'il n'en manque aucune ; `sync-data.mjs` lance ce contrôle et refuse de livrer sinon). Elles sont servies par `web/image-loader.js` (loader `next/image`, pas de `sharp` sur l'hébergement mutualisé) et par le `srcset` de `components/ui/Illustration.tsx` dès qu'on lui passe `sizes`. Une photo source ne doit jamais être nommée `nom-160/400/640/840.webp` : elle serait prise pour une variante (d'où `etudiante-cadree.webp`). Gain mesuré sur `/metiers/` : 994 Ko d'images → 387 Ko sur mobile, 216 Ko sur bureau.
